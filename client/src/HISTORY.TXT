EtherDFS changelog history

--- Donald Flissinger fork (v0.1.0-dev line) ---

fork [2026-07-02] -- native LFN, Phase-2 increment 2 (validated on real
hardware: PC DOS 7.10 + 4DOS 8.00 + EMM386, with Win95LFN=Yes):
 - feat: DIR on an EtherDFS drive under an LFN-aware shell now shows REAL long
   filenames (mixed case, spaces), with sizes and dates. The INT 21h hook
   services the Win95 LFN API for our own drives: 71A0h volume info (local,
   advertises LFN via BX bit14), 714Eh FindFirstFile / 714Fh FindNextFile
   (server round-trip via the new additive opcodes 0x41/0x42, filling the
   caller's 318-byte WIN32_FIND_DATA: long name @0x2C, 8.3 alias @0x130,
   FILETIME or DOS-packed times per SI), 71A1h FindClose, and 71A7h
   FILETIME<->DOS date/time conversion (pure local math, both directions).
   A 4-slot find-handle table (handles 0xEF00|slot) keeps search state
   client-side; foreign handles and other drives chain to the previous
   handler. Everything 8.3 (COMMAND.COM, the INT 2Fh redirector) is untouched
   and re-validated.
 - The blocking server round-trip from the INT 21h hook reuses the proven
   INT 2Fh stack-switch discipline (own save slots) plus a STATELESS nesting
   guard: a handler entered with SS already == DS is nested inside an outer
   switched context and bails/chains instead of resetting the shared resident
   stack. (An earlier flag-based guard could get stuck and killed all 2Fh
   service.)
 - fix: DATASEGSZ 3500 -> 4096. The resident-segment copy must cover the
   WHOLE DGROUP including the transient stack: main()'s parsed args live near
   the stack top and arrived as garbage after the switch, silently dropping
   the auto-discovery flag (server MAC 00:00:00:00:00:00, empty DIR).
 - fix: the installer's DS-relocation patch for the INT 2Fh handler now scans
   for the "MVet" signature (like the INT 21h "MV21" patch) instead of using
   a hardcoded offset that broke whenever the prologue shifted ("DS/SS
   relocation failed"). The install failure path also switches back to the
   original stack before freeing the new segment (it used to free the segment
   its own SS lived in: hang / EMM386 #12 stack fault).
 - fix: Win95 wildcard semantics for LFN masks on the client FINDNEXT
   template ('*' with no dot also wildcards the extension field, and the
   extension scan stops at a second dot) -- byte-identical to the server's
   lfn_mask2fcb, verified by a 17k-mask fuzz harness. Without this, DIR
   listed only directories ("dir" vs "dir *.*" differed).
 - tests: FTCONV.H golden vectors + an exhaustive 46751-date round-trip sweep
   (tests/test_ftconv.c); client/server mask-identity fuzz; the server wire
   test gained a mask-"*" regression that fails the build if files with
   extensions are dropped.

fork [2026-07-01]:
 - fix: DIR under 4DOS now lists files. 4DOS's DIR queries free space
   (INT 21h/AH=36h, and INT 21h/AX=7303h on PC DOS 7.x) BEFORE the listing and
   aborts the whole listing if it gets AX=0xFFFF (invalid drive). DOS answers
   AH=36h locally for our PHYSICAL-flagged redirector drive and never routes it
   to us, returning 0xFFFF. The client now answers AH=36h for its own drives
   directly with a valid volume, so 4DOS proceeds to the file enumeration.
   COMMAND.COM was unaffected (it ignored the bad free-space and listed anyway).
 - fix: DIR "bytes free" footer now shows for our drives under both shells. The
   AH=36h answer above already gives 4DOS its footer, but PC DOS 7.x COMMAND.COM
   (and 4DOS itself) queries free space via INT 21h/AX=7303h (Win95 extended
   free space) first. The client now fills the 7303h ExtGetDskFreSpcStruc for
   its own drives with the same figures instead of failing it, so COMMAND.COM
   also gets a footer. Non-our drives chain to DOS unchanged.
 - fix: the footer now also shows under COMMAND.COM when the CURRENT drive is
   our drive. In that case DIR queries free space with AH=36h/DL=0 (the default
   drive) rather than an explicit drive number; the client now resolves the
   current drive from the SDA (offset 16h) and answers DL=0 for its own drives.
 - feat: report a synthetic volume serial number via INT 21h/AX=6900h, so DIR
   shows a "Volume Serial Number" line for our drives: EDF5-xxxx (high word =
   the EtherDFS ethertype 0xEDF5, low word = the last two bytes of the server
   MAC). Note: 4DOS skips the serial query for network drives, so this surfaces
   under COMMAND.COM. Non-our drives chain to DOS unchanged.
 - fix(server): synthetic volume label is opt-in (only when a label is set).
 - fix(server): expand '*' wildcard to '?' in filename2fcb (FCB mask
   expansion), fixing "dir e:\" under COMMAND.COM.
 - fix(client): drop the doubled 'v' in the version banner.

--- upstream (Mateusz Viste) ---

v0.8.2 [2018-02-03]:
 - support for lock/unlock operations (INT 2Fh,110Ah).

v0.8.1 [2017-04-16]:
 - EtherDFS frames are validated by a cksum (can be disabled with /n),
 - EDF5 frames announce their length to avoid troubles with Ethernet padding,
 - arguments can be passed in any order,
 - /q and /u can be used together.

v0.8 [2017-03-04]:
 - improved self-detection to avoid loading EtherDFS twice,
 - added unloading support (/u),
 - fixed a FindFirst regression (fixes usage under 4DOS),
 - fixed SETATTR action when using a non-FreeDOS attrib command,
 - implemented the 'Seek From End' call,
 - minor memory optimizations,
 - makes sure the redirector API is available before installing,
 - support for multiple drive mappings.

v0.7 [2017-02-11]:
 - MS-DOS compat: flagging newly mapped drive so MS-DOS doesn't ignore it,
 - fixed FindNext behavior so it's compatible with ATTRIB from MS-DOS,
 - implemented the "Special Open" call (used by COPY in MSDOS 5.0 and 6.x),
 - increased timeout retries from 3 to 5 (more reliable on lossy networks),
 - fixed parsing of the MAC address provided on command-line,
 - minor speed optimizations.

v0.6 [2017-02-05]:
 - significantly reduced EtherDFS resident footprint (16K -> 7K),
 - fixed GETATTR (was returning garbage),
 - added support for 'CLOSE FILE', 'RENAME FILE' and 'SET ATTRIBS' actions.

v0.5 [2017-01-31]:
 - first public release.
