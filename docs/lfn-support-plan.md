# EtherDFS Long Filename (LFN) Support — Design & Phased Implementation Plan

**Status:** Proposed
**Repo:** `/mnt/storage/projects/etherdfs-server/` (server `ethersrv.c`/`fs.c`/`fs.h`; client `client/src/`)
**Baseline:** server+client HEAD `4f82889`; client `PVER 0.8.2`, `PROTOVER 2` (`VERSION.H:6`)

---

## 1. Goals & Non-Goals

### 1.1 The actual problem (why this is the fix)

EtherDFS today is SFN/8.3-only end to end. The wire only ever carries either (a) raw, drive-stripped DOS path strings or (b) 11-byte packed FCB names (`name_encoding`). The client owns **only INT 2Fh** (the redirector multiplex); it never hooks INT 21h, so the DOS LFN API (INT 21h/AX=71xx) **never reaches the redirector at all** — "DOS's own LFN layer (INT 21h/71xx) does not redirect LFN operations to the INT 2Fh redirector" (`dispatch_gate`/WHERE 71xx FALLS THROUGH).

Because the etherdfs drive does **not** advertise LFN support, **DOSLFN** (the third-party real-mode LFN TSR) tries to provide LFN itself by *synthesizing* long names on top of the 8.3 names it reads back from the redirector. The destructive failure mode is upstream of our wire: DOSLFN takes a name the **server already produced as a deterministic `~N` 8.3 alias** (e.g. `FILE_I~1.DIZ`, generated by `lfn2sfn` `fs.c:109-167`) and *mangles it* back into an invalid 9-char "long" name (e.g. `FILE_ID_1.DIZ` — the exact `FILE_ID_1.DIZ` case called out in commit `4f82889`'s body). The corruption happens in DOSLFN's guesswork, **not** on our wire and **not** in our server.

**Therefore the fix has three parts, in lockstep:**

1. **Client**: hook INT 21h/71xx for *our drive letters only*, so the etherdfs drive serves LFN natively.
2. **Protocol**: new, additive LFN opcodes carrying real long names + the stable `~N` SFN alias.
3. **Server**: new handlers that return the real long name (retain `d_name`, currently discarded) plus the deterministic SFN alias (already computed, `fs.c:469`).

Once the etherdfs drive answers `71A0h` with **BX bit14 set** ("supports DOS long filename functions", `detection`), DOSLFN **defers** to us for that drive (it chains; it must not return `7100h` for a drive someone else serves) and stops mangling the `~N` names.

### 1.2 Goals

- Native LFN on etherdfs drive(s): create/open/find/rename/delete/attr/dir-ops with names up to 255 chars.
- Return **both** the real long name and a **round-trip-stable** 8.3 `~N` SFN alias in find/open replies (leveraging `4f82889`'s deterministic ordering).
- **8.3 path stays byte-identical on the wire.** Existing opcodes, layouts, header semantics, and `PROTOVER`'s low-7-bits meaning are untouched.
- **Backward/forward compatible**: old client ↔ new server and new client ↔ old server both keep working in 8.3 mode via capability negotiation (never a blind `PROTOVER` bump for existing ops).
- DOSLFN coexistence: serve our drive, chain everything else.

### 1.3 Non-Goals

- No Unicode/UTF-16 storage. Names are codepage bytes (the active DOS OEM codepage); Unicode flags reported as 0 in find results unless/until Phase 3.
- No new handle-based I/O. `716Ch` returns an ordinary DOS handle; subsequent `3Fh/40h/42h/3Eh` ride the **existing** 8.3 read/write/seek/close opcodes unchanged ("the redirector need not provide separate LFN read/write functions", DOS LFN API notes on `716Ch`).
- No cross-drive `7156h` move (return `11h not-same-device`, per spec).
- No change to the raw-Ethernet/`0xEDF5` transport, MAC discovery, seq/retry, or answer-cache model.
- Not fixing the busy-spin core issue (memory `feedback_etherdfs_busyspin`) — orthogonal.

## 2. Architecture

### 2.1 Two independent client hooks

The client keeps its existing **INT 2Fh** hook (legacy 8.3 redirector, `ETHERDFS.C:1981-1993`) **completely unchanged**, and adds a **second, independent INT 21h hook** for the LFN API.

```
                      ┌─────────────────────────────────────┐
   App INT 21h/71xx ─▶│ inthandler21()  (NEW, in BEGTEXT)    │
                      │  if AH != 0x71  ──▶ JMP prev21        │ ── DOSLFN / DOS kernel
                      │  else decode AL, find target drive    │
                      │    not-ours ─────▶ JMP prev21        │ ── DOSLFN serves local drives
                      │    ours ─────────▶ build LFN query    │
                      └──────────────┬──────────────────────┘
                                     │ sendquery() (reused)
   App INT 2Fh/11xx ─▶ inthandler() ─┤ (UNCHANGED legacy 8.3 path)
                                     ▼
                         packet driver  0xF5ED  ──▶  etherdfs server
```

**Install** (transient init, mirror the 2Fh setup at `ETHERDFS.C:1788-1797`/`1981-1993`):
- Save old vector: `AH=35h/AL=21h` → new globals `prev_21_handler_seg/off` (added to `tsrshareddata`, `GLOBALS.H`; extend the `GLOB_DATOFF_*` constants).
- **GET-then-SET ordering is load-bearing**: getting the current 21h vector first means whatever already chained there — *typically DOSLFN* — becomes the link we chain to, so DOSLFN stays behind us for non-our-drive calls (DOS LFN API `chaining` step 1).
- Install `inthandler21()` via `AH=25h/AL=21h`.
- The unload path (`ETHERDFS.C:1709-1729`) must restore 21h too, and **refuse to unhook if the current INT 21h vector no longer points at us** (something hooked on top) — same safety rule as `chaining` close-out.

### 2.2 Dispatch gate (hot path first)

`inthandler21()` runs on **every** INT 21h, so the first test must be the cheapest:

```
inthandler21:
    cmp ah, 71h
    jne  CHAIN21              ; far JMP to prev21 — preserves caller regs+flags+IRET
    ; --- AH==71h only past here ---
    decode AL → subfunction
    resolve target drive:
        path subfns (39/3A/3B/41/43/47*/4E/56/6C/60): DRIVETONUM(first path char) or default drive
        7147h: from DL
        4F/A1: from BX find-handle → look up in our handle table
    if drive not ours (reqdrv>25 || ldrv[reqdrv]==0xFF || handle not ours):
        JMP prev21           ; let DOSLFN/kernel answer — NEVER return 7100h here
    if a sendquery is already in flight (resident 'busy' flag set):
        return CF set, AX=05h ; or chain — see Open Question Q7
    service subfunction → set/clear caller CF image, AX/BX/CX/DX/DI/SI, IRET
```

Use **far JMP, not CALL+IRET**, for the pass-through path so the downstream handler's own IRET returns flags straight to the app (DOS LFN API `chaining`, "Key correctness points"). Note the `_mvchain_intr` trampoline (`CHINT086.ASM:50-72`) assumes the `__interrupt` prologue's fixed BP offsets (`20[bp]/22[bp]/28[bp]`); a second `__interrupt` handler can reuse it, **but the offsets must be re-verified against the 21h handler's generated prologue** (the `ETHERDFS.C:1525` "offset shifts with optimization" caution applies identically).

### 2.3 LFN capability advertisement (how DOSLFN defers)

When DOS/an app issues `AX=71A0h` (GET VOLUME INFORMATION) on a path on our drive, `inthandler21()` answers it **locally** (optionally confirming once with the server via a new `AL_LFN_VOLINFO` op, but the capability answer can be static):

- `CF` clear,
- `BX` = filesystem flags with **bit14 = 1** (supports DOS LFN), **bit1 = 1** (preserves case); bit0 (case-sensitive) = 0, bit2 (Unicode) = 0 (Phase 1/2),
- `CX` = 255 (max component length), `DX` = 260 (max path length),
- `ES:DI` ← ASCIZ FS name string (e.g. `"EDF5"` or `"FAT"`).

This is exactly the detection rule DOSLFN/apps use (`detection`): CF clear + BX bit14 ⇒ LFN available on that drive ⇒ they call our 71xx subfunctions instead of synthesizing. **Crucially, no 71xx subfunction we service for our drive may ever return `AX=7100h`** — `7100h` is reserved for "not us", which we instead chain.

### 2.4 Coexistence model

| Scenario | Result |
|---|---|
| INT 21h, AH≠71h | JMP prev21 immediately (DOSLFN/kernel) |
| 71xx on a non-etherdfs drive | JMP prev21 → DOSLFN serves local drives |
| 71A0h on etherdfs drive | We answer CF clear, BX bit14=1 |
| 71xx (find/open/etc.) on etherdfs drive | We service via new LFN opcodes |
| Legacy 8.3 INT 2Fh/11xx on etherdfs drive | Unchanged legacy path (still works) |
| New client ↔ old server | Capability probe fails → client does NOT hook 21h for that drive (or chains 71xx) → falls back to 8.3 (DOSLFN may run) |
| Old client ↔ new server | Old client never sends LFN opcodes; server's `else return(-1)` (`ethersrv.c:856-857`) is irrelevant since they're never sent; pure 8.3 |

## 3. Protocol Design

### 3.1 Principles (grounded in `extension_points`)

- **Do not bump `PROTOVER`** for existing ops. Bumping either side without the other = total silent incompatibility (every frame dropped, `protocol_version`). The dispatcher's `else return(-1)` (`ethersrv.c:856-857`) makes **new opcodes forward-safe**: an old server silently drops an unknown opcode (no reply → client times out after 5 retries, `ETHERDFS.C:318/395`).
- **New additive opcodes**, not appended bytes on existing replies. Current clients hard-check exact reply lengths (OPEN/SPOPNFIL `==25`, FINDxx `==24`, GETATTR `==9`, etc., `extension_points`), so appending to those would break old clients. New opcodes carry their own length-checked layouts.
- **Capability negotiation, not version bump.** Two mechanisms, used together:
  1. **Feature bit** in `frame[58]` high 3 bits (`reqbuff[58]>>5`, decoded-but-unused `ethersrv.c:277-278`). Client sets **bit5 = "I speak LFN"**; an old server masks it off when computing `reqdrv` via `&31` and ignores it harmlessly.
  2. **Capability probe op** `AL_LFN_CAPS` (extends the `AL_INSTALLCHK 0x00` idea, `new_handlers`): client sends it once at mount; a new server replies with a feature bitmap + a minor **LFN sub-version** (independent of `PROTOVER`). No reply (timeout) ⇒ old server ⇒ stay 8.3.

### 3.2 Opcode assignments

Pick a clean additive block (free per `extension_points`: `0x22..0x2C`, `0x2F+`, `0x40+`). Use **0x40+** to leave the documented free low range untouched and signal "LFN namespace":

| AL | Name | Purpose |
|----|------|---------|
| `0x40` | `AL_LFN_CAPS` | capability/sub-version probe (idempotent) |
| `0x41` | `AL_LFN_FINDFIRST` | 714Eh |
| `0x42` | `AL_LFN_FINDNEXT` | 714Fh |
| `0x43` | `AL_LFN_OPEN` | 716Ch (open existing) |
| `0x44` | `AL_LFN_CREATE` | 716Ch (create/replace) |
| `0x45` | `AL_LFN_GETATTR` | 7143h get (and 4-byte timestamp variants) |
| `0x46` | `AL_LFN_SETATTR` | 7143h set |
| `0x47` | `AL_LFN_RENAME` | 7156h |
| `0x48` | `AL_LFN_DELETE` | 7141h |
| `0x49` | `AL_LFN_MKDIR` | 7139h |
| `0x4A` | `AL_LFN_RMDIR` | 713Ah |
| `0x4B` | `AL_LFN_CHDIR` | 713Bh |
| `0x4C` | `AL_LFN_GETCWD` | 7147h |
| `0x4D` | `AL_LFN_TRUENAME` | 7160h (CL=01h long→short, CL=02h short→long) |
| `0x4E` | `AL_LFN_VOLINFO` | 71A0h (optional; client can answer locally) |

`71A1h` FINDCLOSE and `714Fh`/`71A6h` need no fresh path on the wire when the client holds search state locally (see §4.4); `71A1h` may be purely client-side (free the handle-table slot) plus an optional server-side cursor release.

### 3.3 Wire conventions for LFN names

All LFN names are **length-prefixed**, widening RENAME's 1-byte `L` idea to **2 bytes LE** (`extension_points` explicitly recommends this) so >255 is *structurally* representable even though we cap at 255 for the DOS API:

```
LFNSTR := u16 LE length  ||  <length> bytes of codepage path, drive-stripped, '\' separators, NOT null-terminated
```

Payload ceiling is ~1030 bytes (`FRAMESIZE-60`, `max_sizes`), so a 260-byte path + a 260-byte rename target + headers fit one frame comfortably — **no frame/size extension needed in Phase 1/2.** (READFIL/WRITEFIL chunking is untouched; LFN open returns a handle, then legacy I/O ops carry data.)

**Server-side buffer fix is mandatory** (`max_sizes`): the LFN handlers must **not** reuse the unbounded 256-byte `dos_*[256]` / 16-byte `fname[16]` buffers (`ethersrv.c:366-588`) that overflow on >255 input. New LFN handlers allocate bounded buffers sized ≥ `2 + 255 + slack` and bounds-check the `u16` length against `reqbufflen`.

### 3.4 Concrete request/response layouts

All multi-byte fields **little-endian** (`notes`). `query` at `frame[59]`; feature bit5 set in `frame[58]`; payload at `+60`.

**`AL_LFN_CAPS` (0x40)** — idempotent probe
- Req payload: none (`reqbufflen==0`).
- Resp payload (e.g. 4 bytes): `[0]=LFN_SUBVER` (start at 1); `[1]`=reserved; `[2..3]=feature bitmap LE` (bit0 finds, bit1 open/create, bit2 truename, bit3 attrs, …). `AX=0` ok. Old server: no reply → client treats as "no LFN".

**`AL_LFN_FINDFIRST` (0x41)**
- Req: `[0]=CL allowable-attr` ; `[1]=CH required-attr` ; `[2]=SI date/time format (0=FILETIME,1=DOS)` ; `[3]=reserved` ; then `LFNSTR` filespec (wildcards allowed).
- Resp: `AX=0` ok / `AX=0x12` no-more / `AX=0x02` path-not-found. Payload:

```
[0]      fattr (DOS attr byte)
[1..11]  11-byte FCB SFN alias  (== fprops.fcbname, deterministic ~N, fs.c:469/474)
[12..15] ftime LE u32  (DOS packed date+time, as legacy FINDFIRST [12..15])
[16..19] fsize LE u32
[20..21] server search cursor: dirss (dir id)        — reused from legacy, ethersrv.c:436
[22..23] server search cursor: fpos                   — ethersrv.c:437/467
[24]     reserved
[25..26] u16 LE long-name length  = Ln
[27..27+Ln-1]  long name bytes (codepage)
```
The first 24 bytes are deliberately the **legacy FINDFIRST layout** (`ethersrv.c:414-427`) so server code is copy-then-append (`lfn_change_points` item 1). Client converts `(SFN alias, long name, attr, time, size)` into the 318-byte WIN32_FIND_DATA block (§4.3).

**`AL_LFN_FINDNEXT` (0x42)**
- Req: `[0..1]=dirss` ; `[2..3]=fpos` ; `[4]=CL` ; `[5]=CH` ; `[6]=SI date/time fmt` ; `[7..17]=11-byte FCB search template` (reused from legacy FINDNEXT, `ethersrv.c:439`).
- Resp: identical to FINDFIRST resp. `AX=0x12` no-more.

> Cursor model reuses the legacy `dirss`/`fpos` directory cursor verbatim (`lfn_change_points` item 2). The **client** holds the find-handle→`{drive,dirss,fpos,CL,CH,SI,template}` map; the server stays as stateless as today.

**`AL_LFN_OPEN`/`AL_LFN_CREATE` (0x43/0x44)** — 716Ch
- Req: `[0]=BL open mode` ; `[1]=BH flags` ; `[2..3]=CX create-attrs LE` ; `[4]=DL action code` ; `[5]=reserved` ; then `LFNSTR` long filename (full path, drive-stripped). The leaf is **passed untruncated** to `createfile` (§5.3), bypassing the 8.3 explode (`new_handlers`).
- Resp (mirrors legacy 25-byte OPEN, then appended LFN): `[0]=fattr` ; `[1..11]=SFN alias` ; `[12..15]=ftime` ; `[16..19]=fsize` ; `[20..21]=fileid (start_sector)` ; `[22..23]=CX action-taken (1 opened/2 created/3 replaced)` ; `[24]=resulting open mode` ; `[25..26]=u16 Ln` ; `[27..]=long name`. `AX=0` ok / `AX=2` fail / `AX=3` dir missing.
- Client then has a real DOS handle (from its SFT mapping); subsequent `3Fh/40h/42h/3Eh` use the **existing 0x08/0x09/0x21/0x06** opcodes unchanged.

**`AL_LFN_GETATTR`/`SETATTR` (0x45/0x46)** — 7143h
- GET req: `[0]=BL action (00 get attr,02 size,04 get write time,06 get access date,08 get create time)` ; then `LFNSTR`.
  GET resp: `[0]=fattr` ; `[1..4]=DOS-packed date/time per action` ; `[5..8]=DX:AX physical size (action 02)`. `AX=0`/`AX=2`.
  *(7143h dates are **packed DOS**, not FILETIME — `subfunctions` note; do not mix with 714E.)*
- SET req: `[0]=BL action (01 set attr,03 set write,05 set access,07 set create)` ; `[1..2]=CX` ; `[3..4]=DI date` ; `[5..6]=SI hundredths` ; then `LFNSTR`. Resp: no payload; `AX=0`/`5 readonly`/`2`.

**`AL_LFN_RENAME` (0x47)** — 7156h
- Req: `LFNSTR(old)` immediately followed by `LFNSTR(new)`. Both drive-stripped, same drive (client enforces; cross-drive ⇒ return `AX=0x11` not-same-device locally). Server uses bounded buffers (not the 256-byte `dos_fn1/2`) and reuses `renfile` (`fs.c:769`) after resolving via `resolve_path` for the parent and passing the **untruncated** long leaf.
- Resp: no payload; `AX=0`/`5`/`2`. Preserves the existing LFN-leaf logic (`ethersrv.c:606-635`) — but now the new leaf is genuinely long.

**`AL_LFN_DELETE` (0x48)** — 7141h
- Req: `[0]=SI wildcard flag (0 exact,1 wildcards)` ; `[1]=CL allow-attr` ; `[2]=CH req-attr` ; then `LFNSTR` (wildcards allowed when SI=1). Server reuses `delfiles` (`fs.c:710`) on the resolved long path. Resp: no payload; `AX=0`/`5`/`2`.

**`AL_LFN_MKDIR/RMDIR/CHDIR` (0x49/0x4A/0x4B)** — 7139h/713Ah/713Bh
- Req: `LFNSTR` long dir path. Resp: no payload; `AX=0` / `3` path-not-found / `5` / `0x10` (RMDIR not-empty). CHDIR success requires dir exists (mirror legacy `AX=0/3`, `ethersrv.c:519-522`).

**`AL_LFN_GETCWD` (0x4C)** — 7147h
- Req: `[0]=DL drive` (informational). Resp: `LFNSTR` of the stored CWD **without** drive/colon/leading backslash (`subfunctions` 7147h note). The client stores the per-drive LFN CWD it set via `713Bh` and answers `7147h` mostly **locally** (see Open Question Q4); server op exists as a fallback.

**`AL_LFN_TRUENAME` (0x4D)** — 7160h
- Req: `[0]=CL (00 canonical,01 →short 8.3,02 →long)` ; `[1]=CH SUBST flag` ; then `LFNSTR` input. Resp: `LFNSTR` canonical result (CL=01 ⇒ UPPERCASE 8.3 path; CL=02 ⇒ long path). Server has both forms (`resolve_path` SFN→LFN; `lfn2sfn` LFN→SFN) so it can answer either direction. `AX=0`/`2`/`3`.

### 3.5 Idempotency

The answer cache (`ANSWCACHESZ=16`, keyed on client MAC+seq, `notes`) automatically protects non-idempotent LFN ops (rename/delete/create) on retransmit — a retried frame with the same seq replays the cached reply instead of re-executing. **No new work needed**; just don't make any LFN op assume it executes exactly once.

## 4. Client Implementation

### 4.1 Order of subfunctions

| Priority | Subfns | Phase | Rationale |
|---|---|---|---|
| 1 | `71A0h` volinfo, `714Eh`/`714Fh` find, `71A1h` findclose | 1 | Detection + directory listing are what DOSLFN mangles; biggest visible win. `DIR` and shell name display. |
| 2 | `716Ch` open/create | 1 | Open/create long files; reuse existing handle I/O. |
| 3 | `7160h` truename | 2 | Apps map long↔short; needed for many tools. |
| 4 | `7143h` attrs, `7156h` rename, `7141h` delete | 2 | Full file management. |
| 5 | `7139h/713Ah/713Bh/7147h` dir ops + CWD | 2 | `MD/RD/CD` with long names + correct `7147h` readback. |
| 6 | `71A6h` info-by-handle | 3 | Rarely used; optional. |

### 4.2 New buffers/structs (carved from the 3500-byte `DATASEGSZ`, `tsr_constraints`)

All resident, in the private DATA segment (**never** on the swapped TSR stack at `DS:DATASEGSZ-2`, `ETHERDFS.C:1064-1073`):

- `lfn_pathbuf[260]` — inbound ASCIZ long path (copied from caller DS:DX/DS:SI).
- `lfn_path2buf[260]` — rename destination.
- `lfn_findtab[N]` — find-handle table: `{ u8 inuse; u8 drive; u16 dirss; u16 fpos; u8 cl; u8 ch; u8 si; u8 tmpl[11]; }`. Start with `N=4` (DOS apps rarely nest many LFN searches; bump if needed). Handle value = table index+1 (0/`FFFFh` reserved invalid).
- `lfn_cwd[26][?]` — optional per-drive LFN CWD store (only for our drives; can be a single slot per mounted letter). See Q4 for sizing tradeoff.
- `prev_21_handler_seg/off` in `tsrshareddata`; extend `GLOB_DATOFF_*`.
- A `lfn_busy` byte (reentrancy guard, §4.6).

**Budget note:** two 260-byte buffers + a small find table eat ≈600–700 B of the 3500 B segment, which is *also* the resident stack. This is the single most binding constraint (`tsr_constraints`). If headroom is tight, place `lfn_path2buf` in a union with `lfn_pathbuf` for ops that don't need both simultaneously (only rename needs both).

### 4.3 Building the 318-byte FindData block (714E/714F)

Caller passes `ES:DI` → ≥`0x13E` (318) byte buffer. Fill (offsets per DOS LFN API `find_data_struct`, trust **0x2C/0x130**):

```
00h  DWORD dwFileAttributes      ; from server fattr (low word matches DOS bits)
04h  8     ftCreationTime        ; SI=0 → FILETIME; SI=1 → DOS packed (we have DOS packed from wire)
0Ch  8     ftLastAccessTime
14h  8     ftLastWriteTime        ; primary; from server ftime
1Ch  DWORD nFileSizeHigh = 0
20h  DWORD nFileSizeLow  = fsize
24h  DWORD dwReserved0 = 0
28h  DWORD dwReserved1 = 0
2Ch  260   cFileName             ; the LONG name (ASCIZ) from resp [27..]
130h 14    cAlternateFileName    ; the 8.3 SFN alias (ASCIZ) from resp [1..11], formatted "NAME.EXT"
```
- `CX` (Unicode flags) returned to caller = 0 in Phase 1/2 (no Unicode).
- When `SI=0000h` (FILETIME requested), convert DOS packed date/time → FILETIME on the **client** (small fixed routine; no libc — hand-rolled, `tsr_constraints`). When `SI=0001h`, copy DOS packed directly. *(Confirm whether to do the conversion client-side or request FILETIME from the server — Open Question Q3.)*
- The 8.3 alias at `0x130` is exactly what makes legacy tools and a later 8.3 open land on the right file (`sfn_consistency`).

### 4.4 Find-handle lifecycle

1. `714Eh`: allocate a `lfn_findtab` slot → send `AL_LFN_FINDFIRST` → store returned `dirss/fpos` + the FCB template (server builds it; or client builds from filespec) → fill caller's FindData → return handle (slot+1) in `AX`.
2. `714Fh`: `BX`=handle → look up slot → send `AL_LFN_FINDNEXT` with stored `dirss/fpos/CL/CH/SI/template` → update `fpos` → fill FindData. `AX=0x12` when server says no-more.
3. `71A1h`: `BX`=handle → mark slot free. (Server cursor is stateless/`dirlist`-cached, so no mandatory server round-trip; optionally send a release hint.)
4. Any `714Fh/71A1h` with a `BX` **not** in our table ⇒ JMP prev21 (it's DOSLFN's handle).

### 4.5 Name source

Long names come **directly from the caller's `DS:DX`/`DS:SI` ASCIZ** (up to 260 bytes), *not* from the SDA — the SDA's `fn1`/`fcb_fn1`/`found_file.fname`/`srch_tmpl` are all 8.3/11-byte and cannot carry a long name (`name_source`/`how_to_add_71xx` step 3). The legacy 2Fh path keeps reading the SDA; the 71xx path bypasses it entirely.

### 4.6 TSR / real-mode / reentrancy

Per `tsr_constraints`:
- **All new code in BEGTEXT**, before `begtextend()` (`ETHERDFS.C:1101`), or it's trimmed by the `AH=31h` keep-size (`ETHERDFS.C:2005`). `inthandler21()` + every helper it calls must be resident.
- **No libc** in resident code: use `copybytes`/`mystrlen`/`zerobytes` and `_mvchain_intr`. Hand-roll the DOS-date↔FILETIME and long↔short formatting.
- **8086-compatible** only (shr-by-1 loops, no 186+ opcodes).
- **Self-modifying DS patch**: add a new signature (e.g. `'MV21'`) to `inthandler21()` and a third patch block in `updatetsrds()` (`ETHERDFS.C:1514-1552`); re-verify the hardcoded DS-word offset (`sptr[3]/sptr[4]`) and the unload probe offset (`ETHERDFS.C:1675`) against the generated prologue — both are documented-fragile.
- **Reentrancy**: unlike the 2Fh redirector (always called by DOS in a safe context), INT 21h fires from arbitrary code at arbitrary times and may be re-entered while DOS is non-reentrant.
  - Test `AH==71h` **first and cheapest**; chain instantly otherwise.
  - For our 71xx calls, the app itself called INT 21h, so DOS's reentrancy is the app's concern — but **issue no further INT 21h from inside the handler**, and guard against being re-entered while a `sendquery` (~100 ms blocking, re-enables interrupts) is in flight via the `lfn_busy` flag. If busy on re-entry, fail safely (`CF` set, `AX=05h`) rather than corrupt in-flight state. *(Final busy-policy is Open Question Q7.)*
  - Reuse the same SS:SP stack-swap discipline as `inthandler()` (`ETHERDFS.C:1064-1083`) around any blocking work, since the caller's stack may be tiny.

## 5. Server Implementation

### 5.1 The one essential data change (`new_handlers`/`notes`)

The server **already reads the real long name twice** (`gendirlist` readdir `fs.c:432`, `resolve_sfn_in_dir` readdir `fs.c:848`) but discards it from `gendirlist`. The single load-bearing change:

1. Add `char lfn_name[256];` to `struct sdirlist` (`fs.c:35-40`), next to `sfn_name[14]`.
2. In `gendirlist`, after the qsort + collision loop, `strcpy(newnode->lfn_name, names[ni])` next to the existing `sfn_name` store (`fs.c:469`). Zero cost for legacy ops; they ignore the field.
3. Add a parallel out-param to a new `findfile_lfn()` (or an optional `char *out_lfn` arg to `findfile`, NULL for legacy) so the long name travels to the caller **without disturbing** the 11-byte `fcbname` wire layout legacy ops depend on.

The SFN alias to return is literally `newnode->sfn_name` / `dirlist->fprops.fcbname` (overridden at `fs.c:474`) — **deterministic and round-trip-stable thanks to `4f82889`** (`qsort(cmp_names)` `fs.c:440`, `qsort(cmp_sfn_entry)` `fs.c:856`, identical collision loops `fs.c:454-467`/`859-876`). So `(long, sfn)` advertised by FindFirst resolves to the same real file on a later open (`sfn_consistency`).

### 5.2 New handlers (additive `else if` branches in `process()`, after the existing chain `ethersrv.c:306-858`)

Each follows the existing gating pattern `else if ((query==AL_LFN_xxx) && (reqbufflen>=N))` (`extension_points` item 2):

- **`AL_LFN_FINDFIRST`/`AL_LFN_FINDNEXT`**: copy the `0x1B`/`0x1C` bodies (`ethersrv.c:364-470`), call `findfile_lfn`, emit the legacy 24-byte block **then append** `u16 len + lfn_name` (`lfn_change_points` items 1–2). Reuse `dirss/fpos` cursor unchanged. Parse the filespec from an `LFNSTR` into a **bounded** buffer (not `dos_search_path[256]`'s unchecked memcpy, `max_sizes`).
- **`AL_LFN_OPEN`/`AL_LFN_CREATE`/`AL_LFN_SPOPNFIL`**: copy `0x16/0x17/0x2E` body (`ethersrv.c:673-815`), but **treat the leaf as a long name** — resolve only the *parent dir* via `resolve_path` (`:707`), skip the 8.3 explode/`filename2fcb` squeeze (`:704/:714`), pass the untruncated leaf to `createfile` (`fs.c:571`, reused unchanged). Return real name + SFN alias.
- **`AL_LFN_GETATTR`/`SETATTR`**: copy `0x0F/0x0E` bodies (`ethersrv.c:552-581`/`528`); `resolve_path` already returns real LFN paths, so carry the long leaf through. For GETATTR, pull the name from the cached `dirlist` node rather than re-deriving via `filename2fcb` (`getitemattr` `fs.c:263` would FCB-truncate a raw basename — `notes` caveat).
- **`AL_LFN_RENAME`**: copy `0x11` body (`ethersrv.c:582-650`); resolve both paths, ensure the **destination long leaf is not 8.3-squeezed**, reuse `renfile` (`fs.c:769`). Parse two `LFNSTR`s into bounded buffers (replace `dos_fn1/2[256]`).
- **`AL_LFN_DELETE`**: copy `0x13` body (`ethersrv.c:651-672`); `delfiles` (`fs.c:710`) reused. Honor wildcard/attr flags.
- **`AL_LFN_MKDIR/RMDIR/CHDIR`**: copy `0x03/0x01/0x05` bodies; `remdir`/`changedir`/mkdir reused; bounded buffers replace `dos_dir[256]`.
- **`AL_LFN_TRUENAME`**: CL=01 → run `lfn2sfn`-equivalent over the resolved path components to produce the 8.3 form; CL=02 → `resolve_path` then return the real long path.
- **`AL_LFN_CAPS`**: return sub-version + feature bitmap.

Legacy handlers (`0x01..0x2E`) are **untouched**; the 24-byte/25-byte/9-byte replies (`ethersrv.c:416,458,814`) keep their exact lengths, so non-LFN clients are unaffected (`lfn_change_points` close-out).

### 5.3 Closing the create-path SFN gap (`sfn_consistency`/`notes`)

The known `FILE_ID_1.DIZ` failure: `AL_CREATE`/`SPOPNFIL` explode `dos_full` and pass an 8.3-truncated leaf to `createfile` (`ethersrv.c:704,714,726,751,775`); `filename2fcb`/`lfn2sfn` truncate >8-char basenames with no `~N` at create time, so a 9+char leaf is rejected before reaching a stable alias. The LFN create path **must**:
1. Pass the untruncated long leaf straight to `createfile` (`fs.c:571`), **not** through `explodepath`/`filename2fcb`.
2. Skip the `resolve_sfn_in_dir` miss-path (`fs.c:889-902`) which only handles 8.3 echo (`sfn_consistency` "Remaining gaps").
3. **Only then** derive the SFN alias via the deterministic collision loop. **Factor that loop out** of `gendirlist` (`fs.c:454-467`) into a shared helper `sfn_for_name_in_dir(dir, longname, outsfn)` used by `gendirlist`, `resolve_sfn_in_dir`, **and** create, so the alias a fresh create reports equals what a later FindFirst computes (`new_handlers`). This is essential for round-trip stability of just-created long files.

### Regression fixture set (used in every phase)

Create on the server's exported dir a directory `lfntest/` with at minimum:

| Real name | Expected 8.3 SFN alias |
|---|---|
| `FILE_ID.DIZ` | `FILE_ID.DIZ` (fits) |
| `file_id_long.diz` | `FILE_I~1.DIZ` |
| `file_id_other.diz` | `FILE_I~2.DIZ` |
| `A Long Document Name.txt` | `ALONGD~1.TXT` |
| `report.2026.final.tar.gz` | `REPORT~1.GZ` |
| pre-existing literal `FILE_I~1.DIZ` (a tilde file) | itself / `FILEI_~1.DIZ`-class |
| 200-char name `aaaa…(200).dat` | `AAAAAA~1.DAT` |
| mixed-case `MixedCase.TXT` | `MIXEDC~1.TXT` |

**The core regression assertion (the bug we are fixing):** with the new client serving LFN and DOSLFN's mangling out of the path, `DIR` on `lfntest\` must show the real long names AND `DIR /X` (or a `7160h CL=01` probe) must show the *stable* `~N` alias, and a `COPY FILE_I~1.DIZ` (the 8.3 alias) must open the **same** file FindFirst reported — never an invalid 9-char `FILE_ID_1.DIZ`.

### Phase 1 — Minimal native LFN, **DOSLFN UNLOADED**

**Scope:** server `lfn_name` retention + `findfile_lfn` + create-gap helper; opcodes `AL_LFN_CAPS`, `FINDFIRST/NEXT`, `OPEN/CREATE`, `VOLINFO`, `FINDCLOSE`. Client: INT 21h hook, gate, find-handle table, FindData fill, `716Ch`, `71A0h`. **No DOSLFN running.**

**Tests (DOSLFN not loaded):**
1. `71A0h` on etherdfs drive returns CF clear, BX bit14=1, CX=255, DX=260. On a non-our drive → chains (returns whatever DOS returns).
2. `DIR lfntest\` shows full long names; entries match the fixture table.
3. `714Eh/714Fh/71A1h` cycle: enumerate all fixture entries exactly once, correct order, FindData offsets `0x2C` (long) / `0x130` (8.3 alias) populated; `0x12` after last.
4. `716Ch` create `A Brand New Long File.txt` → file appears with that exact name on the server FS; `COPY CON` writes via existing `0x09` WRITEFIL.
5. **Create-gap regression**: `716Ch` create `file_id_created.diz` (9-char base) succeeds (previously rejected); its reported SFN alias resolves back to it on a fresh open.
6. **8.3 still byte-identical**: run the full legacy 8.3 test (open/read/write/find/rename/delete via INT 2Fh) — unchanged behavior, identical wire frames (capture with the server's BPF / a pcap and diff against a baseline capture).
7. **Old server / new client**: point new client at an unmodified server → `AL_LFN_CAPS` times out → client must NOT hook 21h for that drive (or chain 71xx) → only 8.3 served, no hangs.
8. **New server / old client**: unmodified client → only legacy opcodes seen server-side; LFN branches never entered.

### Phase 2 — DOSLFN coexistence, negotiation, remaining ops

**Scope:** add `7160h truename`, `7143h attrs`, `7156h rename`, `7141h delete`, `7139h/713Ah/713Bh/7147h` dir ops; finalize capability negotiation (feature bit5 + `AL_LFN_CAPS` sub-version); GET-then-SET hook ordering with DOSLFN present.

**Tests (DOSLFN LOADED):**
1. **Hook-order**: load DOSLFN, then load etherdfs client → 21h vector points at us, prev points at DOSLFN. `DIR C:` (local FAT) still long via DOSLFN; `DIR <etherdfs>:` long via us (verify via pcap that local-drive 71xx never hit our wire).
2. **The headline regression — with DOSLFN present**: `DIR <etherdfs>:\lfntest` shows correct long names and the *stable* `~N` aliases; the pre-existing `FILE_I~1.DIZ` tilde file is **not** mangled into `FILE_ID_1.DIZ`. Compare directly to "DOSLFN-only, no etherdfs LFN" run to demonstrate the corruption is gone.
3. **Drive isolation**: 71xx for a non-etherdfs drive always chains; never appears on etherdfs wire.
4. `7156h` rename long→long within drive; cross-drive returns `0x11`. `7141h` delete with/without wildcards (SI=0/1) honoring CL/CH masks.
5. `7143h` get/set attrs and all timestamp actions; verify **packed DOS** dates (not FILETIME).
6. `7160h` CL=01 (long→short) returns the matching `~N`; CL=02 (short→long) inverts it; round-trips for every fixture entry.
7. `713Bh CHDIR` then `7147h GETCWD` returns the same form set (LFN CWD distinct from 8.3 CWD).
8. **Unload safety**: refuse unhook if 21h no longer points at us; clean unload when it does; DOSLFN still functional after our unload.
9. **Negotiation skew matrix**: {old,new}client × {old,new}server — all four behave (LFN only when both new; 8.3 otherwise; no hangs/crashes).

### Phase 3 — Unicode/codepage, edge cases, `71A6h`

**Scope:** codepage handling (declare active OEM codepage; set Unicode flag bits only if truly Unicode); `71A6h` by-handle info; `~N` tunneling edge cases; deep paths; memory hardening.

**Tests:**
1. Names with codepage-specific high-bytes (e.g. CP437 box chars, accented chars) round-trip create→find→open without corruption; `71A0h` BX bit2 reported correctly (0 unless Unicode).
2. 255-char component + ~260-char path: create/find/open at the limit; 256+ rejected cleanly (no overflow — verify the bounded server buffers, contrast with the old unchecked `dos_*[256]` `memcpy`s `max_sizes`).
3. `~N` collision tunneling: 3+ files colliding to the same base (`~1.../~2.../~3...`), enumerate + open each by alias; verify determinism across separate FindFirst and open scans (`sfn_consistency`).
4. Many concurrent find handles (exhaust `lfn_findtab`, verify graceful "no more handles" and chaining of foreign handles).
5. `71A6h` by-handle info (if implemented): 52-byte record, FILETIMEs.
6. Stress: rapid create/delete/rename interleaved with retransmits (force seq replays) → answer-cache idempotency holds (no double-apply).
7. **Memory**: measure resident size before/after; confirm `DATASEGSZ` headroom (stack vs. buffers) still safe under packet-driver rx.

## 7. Risks & Mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| **TSR memory / `DATASEGSZ` 3500 B** exhausted by 260-byte buffers + find table cutting into the resident stack (`tsr_constraints`) | High | Union `lfn_path2buf` with `lfn_pathbuf` except for rename; cap `lfn_findtab` at 4; measure resident size each build; keep all helpers minimal/8086. |
| **Reentrancy** — INT 21h hook fires from arbitrary code while DOS non-reentrant; `sendquery` blocks ~100 ms with interrupts re-enabled (`tsr_constraints`) | High | `AH==71h` test first; `lfn_busy` flag; no further INT 21h from handler; reuse SS:SP swap; fail-safe (CF set) on busy re-entry. |
| **Version skew** — `PROTOVER` bump breaks everything silently (`protocol_version`) | High if mishandled | Never bump `PROTOVER` for existing ops; use additive opcodes + feature bit5 + `AL_LFN_CAPS` sub-version. Validate all four skew combinations (Phase 2 test 9). |
| **Breaking 8.3 clients** by appending to existing replies (hard length checks `==24/25/9/...`) | Medium | New opcodes only; existing reply layouts untouched; pcap-diff legacy frames (Phase 1 test 6). |
| **DOSLFN hook-order** — if etherdfs loads *before* DOSLFN, DOSLFN chains to us and may still intercept our drive | Medium | Document load order (etherdfs **after** DOSLFN, GET-then-SET); detect at install if 21h is already ours; Phase 2 test 1 validates. |
| **Charset/codepage** mismatch (server stores UTF-8 on Linux FS; DOS expects OEM codepage) | Medium | Phase 1/2 assume single OEM codepage byte-for-byte; document the active codepage; Unicode deferred to Phase 3; report BX bit2=0 until real Unicode. |
| **Create-path truncation** leaving long creates impossible / wrong alias (`sfn_consistency`) | Medium | Untruncated leaf to `createfile`; shared `sfn_for_name_in_dir` helper; Phase 1 test 5. |
| **Self-modifying DS-patch offset drift** with optimization (`tsr_constraints`, `ETHERDFS.C:1525/1675`) | Medium | New `'MV21'` signature + patch block; pin compiler flags; assert offsets in a build-time check; verify unload probe offset. |
| **Server unbounded `dos_*[256]` memcpy** overflow on >255 input (`max_sizes`) | Medium | LFN handlers use new bounded buffers + `u16` length checked against `reqbufflen`; never reuse the legacy fixed buffers. |
| **`_mvchain_intr` BP offsets** assume 2Fh prologue; 21h prologue may differ (`CHINT086.ASM:55-58`) | Medium | Verify generated prologue; if mismatched, provide a 21h-specific chain trampoline. |
| Find-handle exhaustion / foreign-handle confusion | Low | Handle = slot+1, validate ownership in 714F/71A1, chain foreign handles. |

### Open Questions (resolve before coding)

- **Q1.** Per `nooit gokken`: confirm the **318-byte FindData layout** (long@`0x2C`, alt@`0x130`, total `0x13E`) and the exact `7143h` register/date-format conventions against RBIL one more time before implementing (research already corroborated via ctyme/fd.lod.bz/fysnet/MS, but verify the specific `714Eh` structure table not re-fetched this session — `find_data_struct` caveat 8).
- **Q2.** Codepage: which OEM codepage do we assume on the wire, and does the server FS store UTF-8 (needing conversion) or already CP-encoded names? Determines whether Phase 1 can be byte-passthrough.
- **Q3.** FILETIME conversion: do it **client-side** (server sends DOS-packed as today) or have the server send FILETIME when `SI=0`? Client-side keeps the wire identical to legacy time fields but adds resident code (`tsr_constraints` no-libc).
- **Q4.** `7147h GETCWD` / LFN CWD: store per-drive LFN CWD **client-side** (resident memory cost) or query the server each time (round-trip + server CWD state)? Win9x kept a separate LFN CWD (`subfunctions` 713Bh note).
- **Q5.** `716Ch` CX "action taken" pitfall — DOS does PUSH CX/POP CX around the redirector entry historically clobbering CX (`subfunctions`/notes 716Ch). Since we own INT 21h directly (not via the 2Fh redirector callback), confirm we control CX on return; verify on real DOS/FreeDOS.
- **Q6.** Whether `AL_LFN_VOLINFO` needs a server round-trip at all, or the client answers `71A0h` purely locally for mounted drives.
- **Q7.** Busy-reentry policy: on re-entry while `lfn_busy`, return `CF`/`AX=05h`, or chain to prev21, or spin? Pick the option least likely to corrupt in-flight find state.
- **Q8.** Frame size: confirm 260+260 byte rename fits the 1090 client buffer / ~1030 payload (it does per `max_sizes`) so **no `FRAMESIZE`/size-field widening** is needed in Phase 1/2; only revisit if a future op needs >1030.
- **Q9.** Whether to also expose LFN truename CL=00 (canonical) or only 01/02 (the per-drive translation primitives the redirector must implement, `subfunctions` 7160h).
